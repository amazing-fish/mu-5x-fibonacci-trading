# 加仓时间契约

Refs #119、#83、#99。以 `21545f860bc5ad06f8b6fd119f0180896899228f` 为修复前基线，保留 #116 与 #118。

## 决策与执行

信息可用时点 ≤ 决策时点 ≤ 最早可执行时点。15m K 线以开盘时间标识，RSI/MACD/high/open 组成的完整候选只在该根收盘（open + 900000ms）后可用。沿用 `build_hourly_context` 在该根开盘已可见的 1h regime，不提前使用未收盘 1h。

共享 `decide_pyramid_add` 仍判断阶段上限、时段、触及原阈值、RSI、MACD 和阶段 3/4 的 regime。返回候选参考价、原加仓阈值及信息可用时间，不产生 Fill。参考价保留原 `max(signal.open, trigger)` 的观察含义，不能成为此前成交的证明，也不决定下一根成交价。

回测将收盘候选封装成仅供紧接下一根 15m 执行的计划，附着于原持仓。不存在真实下一根时，只有候选，不能生成成交。计划只活一根；未触价、时段关闭、时间不连续、持仓已退出或阶段改变均失效，不跨午间/隔夜窗口延期。下一根收盘可以重新生成新候选。

执行前使用信号根已经收盘的 RSI/MACD，以及执行根开盘已可见的最新 1h regime，重新调用同一资格判断；阶段 3/4 若 regime 不符即取消，阶段 2 保留原有规则。执行根收盘指标不能放行或撤销此前的模拟成交。

下一根开盘高于阈值时按该开盘价成交；否则只有该根 high 触及原阈值才按阈值成交。信号根参考价不是限价，不跨根沿用其开盘价。OHLC 只证明该根有触价机会，Fill.time_ms 记录执行根标识；盘中触价发生在该根区间内，不声称知道毫秒级成交时间。

## 风险和结算顺序

继续采用 #118 的保守 OHLC 顺序：非时段杠杆风险 → 本根开始时已有止损 → 执行上一根计划 → 本根收盘更新止损 → 生成下一根候选 → 标记权益。即使开盘已越过加仓阈值，只要该根也触及已有止损，仍按既有风险优先模型退出，不推断盘中高低顺序。

加仓后收紧的止损从下一根生效，不回查执行根先前低点。新入场的初始风险检查、各入场方式的既有处理差异、末根已有风险及有效 pending entry、唯一一次 end_of_data 结算均保持。末根可以执行前一根计划，但不能执行自身收盘候选。

人工复核调用同一候选规则，仅展示参考价和最早可执行时间；候选不自动写入台账。shadow 现有退出检查继续复用止损规则；没有接入加仓模拟或真实订单。

## 边界

不变更指标阈值、5x 杠杆、20/20/20/40 保证金、2/4/6% 加仓阈值、止损算法、日历或严格数据门禁。费用仍沿用既有 Fill 与平仓时确认口径。没有滑点、funding、盘口队列、部分成交或延迟模型。本契约修复加仓时间倒置，不是整体执行引擎或费用记账改造。
